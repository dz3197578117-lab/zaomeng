# 2.1.13 范围清单（功能自检 + 补齐运行诊断）

> 这份清单是 2.1.13 的**验收依据**：每一项都要有「实现 + 验证 + 报告」，
> 做不完就明确标「未做」，不允许标成已完成却没验证。
> 状态只有三种：`未做` / `进行中` / `已完成（附证据）`。

## 背景

2.1.12 交付了「问题捕获」这条线（运行诊断与运行日志分页、采集开关、清除旧日志、
应用内悬浮窗、三层问题捕获、现场元信息）。本版要把用户提出的其余需求**全部**做完。

一条贯穿全版的硬性语义（用户明确要求）：

> **运行日志的「关闭采集」不得影响运行诊断。**
> 采集开关只控制常规日志（logcat）是否持续写入；崩溃、ANR、进程死因、结构化事件、
> 功能自检、概览、启动自检、模型连通性在采集关闭时**都必须照常可用**。
> 某个探针若确实需要日志样本，采集关闭时应报「—（无样本）」而不是 FAIL 或 ✅。

## R1 · 功能自检 + 注册机制 + 未注册可见（进行中）

- [ ] 探针契约（放 `commonMain`）与注册表；单探针抛异常不得影响其它探针或整个诊断
- [ ] 探针必须**廉价 + 可缓存 + 只读**（禁止「检查时顺手修复」业务数据）
- [ ] **35 项高风险探针**：书卷与整理 12 · 会话与对话 12 · 插件 4 · 模型与端侧 3 · 系统 3
      （清单见提交记录与探针实现；含载重项：人设弧线覆盖率与**是否真被注入**、
      时间线**期望值 vs 实际值**、transcript **重复 key**、关系图**悬空引用**、
      **提示词规则键缺失**、8 个内置插件动作、端侧推理截断）
- [ ] **未注册可见**：维护 `KnownFeatures` 单一来源，界面显示「已注册 N 项 / M 个功能未注册」
      且可展开看未注册的功能名
- [ ] 运行诊断页新增「功能自检」区块，导出含探针结果（精简版结论+数字 / 完整版细节）
- [ ] 单测：注册表（注册/枚举/去重/单探针异常隔离/**未注册计算**）+ 3~5 个纯逻辑探针
- [ ] 验收证据：关闭采集后「功能自检」除「无样本」项外与开启时一致

## R2 · 问题清单可用性（面包屑 / 聚合 / 分级 / 保留）

- [ ] **面包屑**：每条问题自动附带发生**之前**的上下文（最近 N 条事件、当时页面、
      内存水位、当前 run/session、采集是否开启）——环形缓冲，截断
- [ ] **问题聚合去重**：同堆栈（崩溃）/ 同签名（事件）归为一组，显示**次数 + 首次 + 最近时间**
- [ ] 严重度分级与默认排序（崩溃 > ANR > 卡死/长任务 > 卡顿 > 视觉信号 > 提示）
- [ ] 保留策略与上限写入概览（环形缓冲 + 字节上限 + 自动裁剪；崩溃与常规事件分别设限）
- [ ] 验收证据：构造 3 条同签名事件 → 清单显示为 1 组、次数 3

## R3 · 呈现与导出

- [ ] 「运行诊断」入口行显示**问题计数**（与探针 FAIL 数一并计入或并列）
- [ ] **导出分级**：精简（概览 + 问题清单摘要 + 探针结论）/ 完整（含日志、完整堆栈、细节）
- [ ] 概览新增「诊断自身状态」区块：**丢事件计数、写入失败计数、采样开销**、当前占用大小
- [ ] 验收证据：两种导出各生成一次，说明体积差异与内容差异

## R4 · 通用上报 + 统一入口兜底（让「还没出来的功能」也能被抓）

- [ ] 通用功能事件上报 API：`report(功能, 操作, 成功/降级/失败, 耗时, 详情)`，成功也要能报
- [ ] 在**已有统一入口**（`runTool` / `repositoryRequest` / 长生命周期 scope 边界）接入兜底：
      任何走统一入口的操作自动被覆盖；**只记录、不改控制流、不吞异常**
- [ ] 报告须给出**具体例子**说明「新增一个功能后不改诊断代码就自动被抓到」
- [ ] 关键路径上被 `runCatching` 吞掉的静默失败，逐步改走通用上报（不只 2.1.12 的 10 处显式埋点）
- [ ] 验收证据：举出至少 2 个「新增 stub 功能 → 自动出现在诊断里」的实例

## R5 · 取消隐私截断（放开完整内容）

- [ ] 允许记录**完整提示词、完整模型输出、完整原文**，只保留**工程上限**
      （单字段上限 + 导出总量上限 + 超限轮转 + 页面显示占用）
- [ ] **API Key / 密钥 / 签名口令仍然绝不记录**（凭证安全，非隐私偏好）——
      须从代码上确认无任何路径可写入
- [ ] 与 R3 的导出分级配套：默认精简，避免几十 MB 的导出无法传递
- [ ] 验收证据：完整导出中确认含完整提示词且**不含任何密钥字段**

## R6 · 盲区补齐

- [ ] **操作轨迹**：导航历史 + 关键操作序列（环形缓冲），并入导出；与面包屑合并呈现
- [ ] **多进程 / WebView**：核查后如实标注覆盖范围（无 WebView / 单进程也要写明）；
      有 WebView 必须处理 `onRenderProcessGone`
- [ ] **可访问性**：关键页面语义节点缺失检测 + 点击目标 < 48dp 检测
      （对比度若成本过高可标「未做」）
- [ ] **数据损坏审计**：解析失败记录路径/原因/大小/mtime/损坏样本；
      关键文件（`session.json` / `run_manifest.json` / `arc.json`）写入审计；
      启动自检增加「关键文件可解析性」

## R7 · 画面与流畅度

- [ ] 帧指标：掉帧率（>16.7ms / >32ms / >100ms 分档）、最长帧、按页面分桶的卡顿直方图
- [ ] 主线程长任务：单次阻塞超阈值的次数 + 当时栈
- [ ] 过度重组 / 重绘计数（闪烁最常见的真实根因，**优先于截图**）
- [ ] 图片同 URL 重复请求/取消计数
- [ ] 布局跳动：关键节点 size/position 短时位移
- [ ] 截图差分「疑似闪烁」：**默认关闭**、低频采样、**像素只在本地内存比较——
      不落盘、不外传、不进导出**；只输出「区域 + 变化次数 + 时间」统计
- [ ] 措辞如实：只能写「疑似闪烁（某区域 300ms 内变化 7 次）」，**不许写「检测到 bug」**
- [ ] 验收证据：从代码上确认像素无落盘/外传路径（grep `PixelCopy`/`MediaProjection` 等）

## 交付纪律（每一轮都适用）

1. 改动留在工作区，由我复核后才提交；实现方不 `git add/commit/push`。
2. 每轮必须跑：`:server:jvmTest`、`:feature:settings:jvmTest`、相关 `compileKotlinJvm` /
   `compileAndroidMain`；能用就跑 `:app:androidApp:assembleDebug`。
3. 报告必须逐条写：**做了哪些 / 没做哪些 / 做不到哪些 / 实际命令与结果 / 未验证的边界**。
4. 做不到的项**不允许**用「已支持」措辞掩盖；不许为了好看硬塞未验证实现。
5. 端点或字段变更必须同步 `docs/server-api.md`；提示词变更必须三处同步并过
   `./scripts/check-prompt-sync.sh`。

## 已知的验收风险（提前说明）

- **无真机验证**：本版大量能力（帧指标、ANR 看门狗、端侧推理状态、TTS 绑定、
  悬浮窗拖动）只有在真机上才有真实值。**编译 + 单测 + 打包通过 ≠ 真机可用**，
  报告中必须区分这两者。
- **画面与流畅度的阈值**需要真机校准；截图差分的采样率与开销尤其如此。
  这部分即便「实现完成」，也应视为「待真机确认」。
