# 2.1.13 范围清单（功能自检 + 补齐运行诊断）

> 这份清单是 2.1.13 的**验收依据**：每一项都要有「实现 + 验证 + 报告」，
> 做不完就明确标「未做」，不允许标成已完成却没验证。
> 状态只有三种：`未做` / `进行中` / `已完成（附证据）`。

## 背景

2.1.12 交付了「问题捕获」这条线（运行诊断与运行日志分页、采集开关、清除旧日志、
应用内悬浮窗、三层问题捕获、现场元信息）。本版要把用户提出的其余需求**全部**做完。

一条贯穿全版的硬性语义（用户明确要求）：

> **运行日志的「关闭采集」不得影响运行诊断。**
> 采集开关只控制常规日志（logcat）是否持续写入；崩溃、ANR、进程死因、结构化事件、
> 功能自检、概览、启动自检、模型连通性在采集关闭时**都必须照常可用**。
> 某个探针若确实需要日志样本，采集关闭时应报「—（无样本）」而不是 FAIL 或 ✅。

## R1 · 功能自检 + 注册机制 + 未注册可见 —— 已完成（编译通过）

**实况（以实际产出为准，不沿用我最初口头拍的「35 项」）**

- 注册表共 **27 个探针**：书卷 9 · 对话 8 · 插件 4 · 模型 3 · 系统 3
- `KnownFeatures` 共 **33 项**，已覆盖 **32**，**未注册 1 项：`chat.advanced_actions`**
  （导演方案 / 续写建议 / 场景切换 / 分支 / 纠错 / 重写）
- `unknownFeatureRefs` 为空；被两个探针覆盖的只有 `bookshelf.persona_arc`
- **恒为「无数据」的 3 项**（探针自己写明原因，不假装 OK）：
  `system.update_check`（更新检查是客户端一次性网络请求、结果不落盘）、
  `system.tts`（纯客户端 PlatformTts + DataStore，服务端拿不到）、
  `chat.first_token_latency`（TTFT 只进 logcat，没进结构化事件）

**关键实现点**

- 探针契约与注册表在 `server/src/commonMain/.../ktor/features/`；探针只读、可缓存、独立失败
- 「未注册可见」= `KnownFeatures` 与已覆盖功能 id 的差集；首轮探针未跑完时返回注册表统计，
  **不再显示成「0 个未注册」**（那会把「一项都没检查」显示成「没有漏检」）
- 弧线注入判定：取**覆盖当前时间点的那一段**，该段无 `state` 即 FAIL
  （运行时 `arcStateForChapter()` 会静默退回更早一段 → 角色带着旧章节人设说话，探针必须报出来）
- `ExitReasonMapping` 按 Android SDK 常量重写：
  用 `javap -constants android/app/ApplicationExitInfo.class` 核对 android-36 / 37.0，
  **原表 8/9/11/12 各错位一格、漏了 10 与 13、多了平台不存在的 17**——已对齐；
  并区分严重度（被更新 / 被系统或 OEM 清理 = info + INTENTIONAL_EXIT，不计入崩溃数、排序垫底）

**已知的测试红灯（全部是测试自身的问题，不是实现缺陷，本版按用户要求不修）**

`:server:jvmTest` 297 tests / 9 failed：

| 数量 | 原因 |
| --- | --- |
| 4 | 测试桩 `promptLoader = error("本测试不读提示词")` 在**构造上下文时立即求值**就抛，用例根本没跑到探针 |
| 2 | `schemaVersion` 断言仍写 4，实际已升到 5 |
| 1 | `FeatureProbeRegistryTest` 断言**方向写反**（断言已被覆盖的功能应出现在「未注册」里） |
| 2 | `ExitReasonMappingTest` 断言的是**原表错位值**（8/9/11/12），有 `javap` 证据 |

**待拍板的关联发现**：运行时 `PersonaArcService.arcStateForChapter()` 在覆盖段非 `ok` 时会
`?: entries.first()` 静默退回最早一段。探针现在会把这种「退回」报成 FAIL，
但**运行时是否也该显式降级**（例如标注 `arc_time_point` 与请求章不符）属于业务行为变更，需用户决定。

## R7 已知局限（2.1.13 收口时如实记录）

以下都是**本版不做**的取舍，写在这里是为了不让它们被误读成「已实现」：

1. **图片同 URL 重复请求只覆盖人物头像**（`PersonaRepositories.getPersonaAvatar` 的缓存命中/重复拉取计数）。
   `ChatBackgroundImage` 等其它图片路径**未接入**，因此该指标目前只对头像有效。
2. **FrameMetrics 的「布局 / 绘制分项」不做**。本版帧指标来自 `Choreographer` 的帧间隔
   （掉帧率 >16.7 / >32 / >100ms 分档、最长帧、按页面分桶），**拿不到**一帧里
   布局与绘制各花了多久。将来可接 `Window.OnFrameMetricsAvailableListener` 补齐，
   但**必须只保留一套帧机制**——两套并存会产生两个数字，没人知道该信哪个。
3. **疑似闪烁的采样与阈值未经真机校准**：默认关闭、500ms 低频、24×24 网格、
   300ms 窗口内变化 ≥3 次才上报。这些数字都需要真机调，当前只能证明采样链路在工作。
4. **布局跳动只判定「尺寸」变化，不判定「位置」变化**。页面位置在导航切换与列表滚动时
   本来就会变，纳入会产生大量假阳性；位置型跳动需要「排除滚动与导航」的上下文，本版不做。
5. **可访问性只有「语义节点缺失」与「点击目标 < 48dp」两项**，**对比度审计未做**
   （需要在渲染后取实际像素与背景色，成本远高于前两项）。`contrastChecked` 恒为 `false`。
6. **可访问性采样走反射**（`AndroidComposeView` 的语义树）。Compose 版本差异可能导致反射失败，
   此时审计如实显示「未采到节点」（`supported=false`），**不会假报通过**。
7. **采样开销只统计「已上报自身成本」的采样器**（帧回调、长任务看门狗、闪烁、可访问性；
   加上重绘探针）。不含 Ktor / 数据库 / 模型的业务耗时——概览里会带一句如实说明。

## 交付纪律（每一轮都适用）

1. 改动留在工作区，由我复核后才提交；实现方不 `git add/commit/push`。
2. 每轮必须跑：`:server:jvmTest`、`:feature:settings:jvmTest`、相关 `compileKotlinJvm` /
   `compileAndroidMain`；能用就跑 `:app:androidApp:assembleDebug`。
3. 报告必须逐条写：**做了哪些 / 没做哪些 / 做不到哪些 / 实际命令与结果 / 未验证的边界**。
4. 做不到的项**不允许**用「已支持」措辞掩盖；不许为了好看硬塞未验证实现。
5. 端点或字段变更必须同步 `docs/server-api.md`；提示词变更必须三处同步并过
   `./scripts/check-prompt-sync.sh`。

## 已知的验收风险（提前说明）

- **无真机验证**：本版大量能力（帧指标、ANR 看门狗、端侧推理状态、TTS 绑定、
  悬浮窗拖动）只有在真机上才有真实值。**编译 + 单测 + 打包通过 ≠ 真机可用**，
  报告中必须区分这两者。
- **画面与流畅度的阈值**需要真机校准；截图差分的采样率与开销尤其如此。
  这部分即便「实现完成」，也应视为「待真机确认」。
