# 语音朗读：真机验证清单

> 这份清单存在的理由：**开发环境无法验证声音**。
> 代码、编译、纯逻辑测试都能在本机跑，但「合成是否成功、播放是否正常、两个角色听起来是否真的不同」
> 只能在装了包的手机上判断。下面每一项都写清「怎么验」与「失败时看哪里」，不要把未知当成已知。

## 一、已经在本机验证过的（有证据）

| 项 | 证据 |
| --- | --- |
| 声线派生与情绪/标点韵律 | `SpeechVoiceTest`（31 例）：确定性、不同角色不撞车、边界收束、叹号不叠加 |
| 模型目录与路径拼装、完整性判定、下载计划 | `NeuralVoiceCatalogTest`（16 例）+ `NeuralSpeechPathsTest`（13 例） |
| 引擎选择与**降级原因** | `SpeechEngineSelectionTest`（8 例）：四种降级各有可读原因 |
| 下载服务（校验、跳过、取消、删除） | `VoiceModelDownloadServiceTest`（15 例）：含目录穿越与不受信主机 |
| 语音界面状态 | `VoiceModelUiStateTest`（8 例）：体积显示、就绪判定、下载源回落 |
| 引擎能编译并打进包 | 完整 APK 构建通过；`lib/` 下**只有 arm64-v8a**，另三个 ABI 被过滤掉（省 91 MB） |

## 二、**完全未验证**的部分（本机听不到）

- 合成是否真的产出音频、`AudioTrack` 播放是否正常；
- 说话人编号听起来是否真的像**不同的人**（这是整个特性的目标）；
- 119 MB 模型在你的机器上加载耗时、内存是否吃得住；
- 语气起伏是否自然（还是仍然「机械」）。

## 四、已知限制（不是缺陷，是引擎能力边界）

- **神经引擎不支持音高**。sherpa-onnx 的合成入口是 `generate(text, sid, speed)`——只有说话人编号与语速。
  音量在**播放侧**施加（`AudioTrack.setVolume`），所以低语这类情绪仍可表达；**音高不行**，
  要做得对合成出的 PCM 变调（会有金属音风险），目前**没有做**。
- **系统 TTS 在中文手机上通常只有 1~2 个音色**，所以「每人不同音色」这件事只有神经引擎能真正做到；
  系统引擎下的角色差异靠音高/语速/音量表达。
- **`voice_desc`（如「低沉沙哑」）不参与推导**：它是给人看的自由描述。
  代码刻意不去猜它的意思——猜错会让角色声音不对且难以解释；请用 `voice_pitch` / `voice_speed` 明确指定。
