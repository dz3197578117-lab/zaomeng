# 造梦能做什么

> 本文面向**使用者**，按能力域介绍造梦现在具备的功能，并标注**从哪个版本开始有**。
> 内容由各版本 APK 的更新日志（[CHANGELOG](../CHANGELOG.md) 与 [发布说明](../.github/release-notes/)）汇总而来。
> 想看逐版本改了什么的细节，去 CHANGELOG；想自己构建或发版，看[发布 Android 版](release-android.md)。

造梦把一本中文小说**整理**成可对话的人物与关系，再让你**进入小说**和人物演下去。

一句话流程：**导入书卷 → 整理（蒸馏）→ 选人物与起始章 → 开演**。

---

## 1. 书卷与整理

| 能力 | 说明 | 起始版本 |
|---|---|---|
| 导入书卷 | 支持 `.zaomeng-run.zip` 书卷包导入导出；导入走路径安全校验 | 基础能力 |
| 文本整理（蒸馏） | 把小说正文蒸馏成**人物档案**、**关系图谱**、章节索引与原文证据 | 基础能力 |
| 逐块蒸馏与合并 | 长文本自动分块抽取再合并，避免一次生成填不满字段 | 基础能力 |
| 断点续跑 | 整理中断后可继续，不必从头再来 | 基础能力 |
| **逐章人设弧线** | 每个角色按**章**存一份「那个时间点」的状态：身份与处境、目标、信条、应激反应、关系阶段、喜恶，以及**该章结束前已经知道的事** | 2.1.8 |
| 弧线的稳定性设计 | 说话风格、外貌、习惯等**稳定特征不进弧线**，仍取人物档案——换时间点不会换掉角色的「味道」 | 2.1.8 |
| 章节索引 | 自动分章并记录精确字符区间；弧线的时间点与章节一一对应 | 基础能力 |
| 整理耗时可控 | 非流式生成超时 60 秒 → 300 秒，蒸馏不再中途超时失败 | 2.1.5 |
| 可读的失败原因 | 超时/断连给中文提示，而不是原始异常串 | 2.1.5 |

## 2. 对话与演出

| 能力 | 说明 | 起始版本 |
|---|---|---|
| 多角色对话 | 一次回复可有多个人物说话，支持内心独白 | 基础能力 |
| 三种身份 | **旁观**（看人物自己演）/ **扮演**（你代入已有角色）/ **入场**（以你自己入场） | 基础能力 |
| 从任意章开始 | 选起始章，开场接着这一章的原文往下演，不照抄原文 | 基础能力 |
| 场景卡 | 指定或按人物与格式推荐场景 | 基础能力 |
| **剧情导演** | 选一个方案（推进剧情／放慢情绪／加强冲突／切换视角），由导演指令引导这一拍 | 2.1.3 强化 |
| **第四面墙** | 你以「作者」身份从故事外向角色下指令 | 基础能力 |
| **强制执行** | 导演与第四面墙都可开启：角色必须落实指令，**不得拒绝、弱化或推迟**；但仍可保留情绪（不满、抱怨、讲条件） | 2.1.7 |
| 续写建议 | 给出可直接发送的多个走向，并附带锚点引用 | 基础能力 |
| 分支与回退 | 对话可分叉、可重新生成某一轮 | 基础能力 |
| 长对话不越聊越卡 | 流式回复解析改为增量投影，长会话不再逐渐变慢 | 2.1.3 |
| 断连不丢这一轮 | 网络瞬断在读首字节前会自动重试 | 2.1.5 |

## 3. 人物与时间线

| 能力 | 说明 | 起始版本 |
|---|---|---|
| **身份与性格跟随时间线** | 从第几章开局，角色就是那个时间点的样子；**不会**从第一章开局却带着全书之后的认知（不剧透） | 2.1.8 |
| 静态 / 活跃分层 | 稳定特征取人物档案；身份、目标、信条、关系阶段、已知信息取当前时间点那一段 | 2.1.8 |
| 不剧透约束 | 提示词明确要求：该时间点**不知道**的事要表现为不知道，也不得预告未来走向 | 2.1.8 |
| **时间点随剧情推进** | 聊下去时间点会自己往前走（每 4 轮推进一章，从起始章起算）；推进是**推导**出来的，重试同一轮不会多推进 | 2.1.9 |
| 界面可见 | 会话上方显示当前时间点（如「时间点：第 5 章」） | 2.1.9 |
| 换时间点 | 想跳到别的时间点，按那个起始章**新建会话**即可 | 2.1.9 |

## 4. 模型接入

| 能力 | 说明 | 起始版本 |
|---|---|---|
| 云端模型 | 任意 OpenAI 兼容端点；内置商汤 SenseNova、硅基流动、月之暗面 Kimi、智谱 GLM、MiniMax 等预设 | 2.1.2 |
| 从接口拉取模型清单 | 填好地址即可拉取该端点可用模型 | 2.1.2 |
| **端侧本机推理** | APK 内嵌 llama.cpp 运行时：导入或下载 `.gguf` 模型，本机跑推理，**不填 API Key 也能用** | 2.1.2 |
| 端侧参数 | 上下文长度、线程数、关闭思考（端侧解码慢，思考会成倍放大延迟） | 2.1.2 |
| 按档案配置超时 | 模型档案可单独设 `timeout_seconds` | 2.1.5 |
| 本机模型独立成页 | 「本机模型（端侧）」从模型档案编辑页拆出，编辑 API 档案时不再被端侧配置干扰 | 2.1.11 |
| 一键启用本机推理 | 在端侧页启动模型后点「启用本机推理」，自动创建/更新本地档案并设为当前模型 | 2.1.11 |

## 已修复的重要问题（说明稳定性来源）

| 问题 | 根因 | 版本 |
|---|---|---|
| 插件/剧情导演一用就闪退 | `ChatToolsDelegate` 成员扩展自递归 → 主线程栈溢出（**所有工具流程都受影响**） | 2.1.6 |
| 同一句回复冒出多个气泡 | 分页前插不去重 + 服务端缺 turnId 幂等 → 同一条消息进列表两次 | 2.1.6 / **2.1.10** |
| 对话闪退（LazyColumn key 重复） | 同上：两条相同消息的列表 key 完全相同，Compose 直接抛异常 | **2.1.10** |
| 角色名混进字面引号（`"李慧英"`） | 会话创建/名单拼装/解析/读取四处都不归一化 → 同一角色同时出现在允许与禁止名单，触发解析失败重试 | **2.1.11** |
| 长对话越聊越卡 | 流式解析每次重解析整段 | 2.1.3 |
| 蒸馏 60 秒超时失败 | 默认超时不足以跑完一次内容提取 | 2.1.5 |
| 应用内显示旧版本号 | 版本号手写在源码里 | 2.1.5 |

## 约定与边界

- **数据在你本机**：书卷、会话、模型配置都存在应用私有目录；诊断数据仅存本机，**导出由你手动触发**。
- **密钥**：只经 Android Keystore 安全存储，**不会**出现在日志或诊断导出里。
- **native 崩溃**：目前能拿到「发生了 native 崩溃 + 信号 + 进程死因」，**拿不到完整 native 堆栈**（需要引入 Crashpad，尚未做）。
- **旧书卷**：没有逐章弧线的旧书卷会退回「单一人物档案」行为，无需迁移；想让旧书卷带上弧线，重新整理一次即可。

## 还在路上

- **功能自检（健康探针）**：让人设弧线、时间线推进、会话完整性、关系图、各插件动作等**自己报告是否正常运行**，并把「有哪些功能还没被检查」显示出来。
- **画面与流畅度**：掉帧率、过度重组、布局跳动、闪烁信号检测。
- **「失败但不报错」的自动捕获**：通用上报接口 + 统一入口兜底。
