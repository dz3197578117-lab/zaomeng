# 造梦能做什么

> 本文面向**使用者**，按能力域介绍造梦现在具备的功能，并标注**从哪个版本开始有**。
> 内容由各版本 APK 的更新日志（[CHANGELOG](../CHANGELOG.md) 与 [发布说明](../.github/release-notes/)）汇总而来。
> 想看逐版本改了什么的细节，去 CHANGELOG；想自己构建或发版，看[发布 Android 版](release-android.md)。

造梦把一本中文小说**整理**成可对话的人物与关系，再让你**进入小说**和人物演下去。

一句话流程：**导入书卷 → 整理（蒸馏）→ 选人物与起始章 → 开演**。

---

## 1. 书卷与整理

| 能力 | 说明 | 起始版本 |
|---|---|---|
| 导入书卷 | 支持 `.zaomeng-run.zip` 书卷包导入导出；导入走路径安全校验 | 基础能力 |
| 文本整理（蒸馏） | 把小说正文蒸馏成**人物档案**、**关系图谱**、章节索引与原文证据 | 基础能力 |
| 逐块蒸馏与合并 | 长文本自动分块抽取再合并，避免一次生成填不满字段 | 基础能力 |
| 断点续跑 | 整理中断后可继续，不必从头再来 | 基础能力 |
| **逐章人设弧线** | 每个角色按**章**存一份「那个时间点」的状态：身份与处境、目标、信条、应激反应、关系阶段、喜恶，以及**该章结束前已经知道的事** | 2.1.8 |
| 弧线的稳定性设计 | 说话风格、外貌、习惯等**稳定特征不进弧线**，仍取人物档案——换时间点不会换掉角色的「味道」 | 2.1.8 |
| 章节索引 | 自动分章并记录精确字符区间；弧线的时间点与章节一一对应 | 基础能力 |
| 整理耗时可控 | 非流式生成超时 60 秒 → 300 秒，蒸馏不再中途超时失败 | 2.1.5 |
| 可读的失败原因 | 超时/断连给中文提示，而不是原始异常串 | 2.1.5 |

|---|---|---|

| 从任意章开始 | 选起始章，开场接着这一章的原文往下演，不照抄原文 | 基础能力 |

| **剧情导演** | 选一个方案（推进剧情／放慢情绪／加强冲突／切换视角），由导演指令引导这一拍 | 2.1.3 强化 |
| **第四面墙** | 你以「作者」身份从故事外向角色下指令 | 基础能力 |
| **强制执行** | 导演与第四面墙都可开启：角色必须落实指令，**不得拒绝、弱化或推迟**；但仍可保留情绪（不满、抱怨、讲条件） | 2.1.7 |
| 续写建议 | 给出可直接发送的多个走向，并附带锚点引用 | 基础能力 |

| **每个角色不同的声音** | 朗读按**说话人**取声线：作者在人物包里填过 `voice_name` / `voice_pitch` / `voice_speed` 就用填的，没填则**按角色名确定性派生**——同一角色在每次会话、每次启动都是同一条声线，不会今天一个声音明天另一个 | **2.1.19** / 重新移植：**2.3.0** |
| **逐句语气起伏（不是平读）** | 按这一句的**情绪**（本地关键词识别，离线、确定性）与**标点**调整语速/音量/音高：愤怒更快更响、悲伤更慢更低、省略号放慢收尾、叹号只按一次计。偏移量刻意很小，避免听成「变声怪」 | **2.1.19** / 重新移植：**2.3.0** |

## 3. 人物与时间线

| 能力 | 说明 | 起始版本 |
|---|---|---|
| **身份与性格跟随时间线** | 从第几章开局，角色就是那个时间点的样子；**不会**从第一章开局却带着全书之后的认知（不剧透） | 2.1.8 |
| 静态 / 活跃分层 | 稳定特征取人物档案；身份、目标、信条、关系阶段、已知信息取当前时间点那一段 | 2.1.8 |

| **时间点随剧情推进** | 聊下去时间点会自己往前走（每 4 轮推进一章，从起始章起算）；推进是**推导**出来的，重试同一轮不会多推进 | 2.1.9 |
| 界面可见 | 会话上方显示当前时间点（如「时间点：第 5 章」） | 2.1.9 |
| 换时间点 | 想跳到别的时间点，按那个起始章**新建会话**即可 | 2.1.9 |

## 4. 模型接入

| 能力 | 说明 | 起始版本 |
|---|---|---|
| 云端模型 | 任意 OpenAI 兼容端点；内置商汤 SenseNova、硅基流动、月之暗面 Kimi、智谱 GLM、MiniMax 等预设 | 2.1.2 |
| 从接口拉取模型清单 | 填好地址即可拉取该端点可用模型 | 2.1.2 |
| **端侧本机推理** | APK 内嵌 llama.cpp 运行时：导入或下载 `.gguf` 模型，本机跑推理，**不填 API Key 也能用** | 2.1.2 |
| 端侧参数 | 上下文长度、线程数、**GPU 层数**、关闭思考（端侧解码慢，思考会成倍放大延迟） | 2.1.2 / GPU 层数：2.1.15 |
| **内置模型清单** | 点模型名即**自动下载并选中**，不用自己找直链；已下过的同名文件不重下，只选中 | 2.1.15 |
| 下载源可选 | 官方 HuggingFace 与 hf-mirror 镜像；两者 `resolve` 直链同构，换源只换主机名 | 2.1.15 |
| **模型的「能力来源」标注** | 每个清单项都写明：确切仓库、发布者（及是否官方）、上游基座、元数据读取日期与下载量、上游模型卡地址。**本项目没有评测过这些模型**，能力以模型卡为准 | 2.1.15 |
| **端侧 GPU 加速（Adreno / OpenCL）** | ⚠️ **默认不随包**。OpenCL 后端可编（上游已验机型含 Snapdragon 8 Elite / Adreno 830），但它引入非系统依赖 `libOpenCL.so`；而 Android 的 linker **不搜索可执行文件所在目录**，导致 2.1.16 / 2.1.17 随包分发时端侧**在加载阶段就起不来**（不是"用不上 GPU"，是整个本机推理不可用）。**2.1.18 起已从随包产物移除**（自包含），构建侧仍保留 `GGML_OPENCL=1`，待真机验证后再定 | 2.1.16 / 随包撤回：**2.1.18** |
| **端侧 CPU 内核（Arm KleidiAI）** | 编译改用 Arm 优化微内核，按**运行时**检测到的 CPU 特性派发（dotprod / fp16 / i8mm），老机型自动回退——不是靠抬高全局编译基线（那会让老机型直接崩）。**2.1.15 及更早的 APK 不含它** | 2.1.16 |
| **离线神经朗读（sherpa-onnx 多说话人中文）** | 随包内置引擎（仅 arm64-v8a，安装占用约 +30 MB），与系统 TTS **二选一**（入口：设置首页「朗读与语音 → 离线神经语音」独立页）。神经引擎给每个角色**真正不同**的音色（多说话人模型的说话人编号）。⚠️ **不支持音高**——引擎合成入口只有说话人编号与语速；语速与音量可用 | **2.1.19** / 重新移植：**2.3.0** |
| **语音模型按需下载** | 多说话人中文模型**不随包**，在「离线神经语音」独立页按需下载（119 MB 起）；**不需要选下载源**——自动按「镜像 → 官方」尝试，并在界面显示正在换源（官方站在国内会先卡掉一次连接超时才失败）；已存在且大小一致的文件会跳过，不必整个重下 | **2.1.19** / 独立入口与自动选源：**2.1.20** / 重新移植：**2.3.0** |
| 按档案配置超时 | 模型档案可单独设 `timeout_seconds` | 2.1.5 |
| 本机模型独立成页 | 「本机模型（端侧）」从模型档案编辑页拆出，编辑 API 档案时不再被端侧配置干扰 | 2.1.11 |
| 一键启用本机推理 | 在端侧页启动模型后点「启用本机推理」，自动创建/更新本地档案并设为当前模型 | 2.1.11 |

## 已修复的重要问题（说明稳定性来源）

| 问题 | 根因 | 版本 |
|---|---|---|
| 插件/剧情导演一用就闪退 | `ChatToolsDelegate` 成员扩展自递归 → 主线程栈溢出（**所有工具流程都受影响**） | 2.1.6 |
| 同一句回复冒出多个气泡 | 分页前插不去重 + 服务端缺 turnId 幂等 → 同一条消息进列表两次 | 2.1.6 / **2.1.10** |
| 对话闪退（LazyColumn key 重复） | 同上：两条相同消息的列表 key 完全相同，Compose 直接抛异常 | **2.1.10** |
| 角色名混进字面引号（`"李慧英"`） | 会话创建/名单拼装/解析/读取四处都不归一化 → 同一角色同时出现在允许与禁止名单，触发解析失败重试 | **2.1.11** |
| 长对话越聊越卡 | 流式解析每次重解析整段 | 2.1.3 |
| 旧书卷角色名带引号时崩掉整轮对话生成 | 档案路径用原始角色名拼，在部分系统上无法表示 → 读取抛异常会带走整轮生成 | **2.1.14** |
| 对话失败时把「内容被提供方拒绝」报成应用故障 | 审核判据只认文案，漏了上游机器可读的 `code`（商汤 `data_inspection_failed`） | **2.1.15** |
| 设置聊天背景后闪退 | 大图解码**没有下采样**：9216×6144 的照片按 ARGB_8888 是 216 MB，超过 Android `Canvas` 的 100 MB 硬上限；而它抛在**绘制期**，所以加 `try` 兜不住。现按目标长边与字节上限算 `inSampleSize` 两趟解码（216 MB → 3.4 MB） | **2.1.17** |
| **朗读完全没声音（Android 11+）** | AndroidManifest 缺 `<queries>` 里的 `android.intent.action.TTS_SERVICE`：targetSdk 30+ 时包可见性限制会让 App **枚举不到任何 TTS 引擎**，`TextToSpeech` 初始化直接回调 ERROR，表现为「点朗读没声音也没有任何报错」。回退语音特性时这条声明被一起删掉了，**2.3.0 补回** | **2.3.0** |
| **端侧推理整个起不来（2.1.16 引入的回归）** | 随包二进制多了非系统依赖 `libOpenCL.so`，而 App 起子进程时没设 `LD_LIBRARY_PATH`，Android 的 linker 又不搜索可执行文件同目录 → `CANNOT LINK EXECUTABLE ... library "libOpenCL.so" not found`。修复：二进制退回**自包含**（NEEDED 只剩系统库），并在 spawn 时显式设置 `LD_LIBRARY_PATH` | **2.1.18** |
| 蒸馏 60 秒超时失败 | 默认超时不足以跑完一次内容提取 | 2.1.5 |
| 应用内显示旧版本号 | 版本号手写在源码里 | 2.1.5 |
| **角色回复后本轮消息从界面消失** | 去重按「同一 turnId 只保留最后一条」实现，但一个 turnId 对应**一整轮**（用户消息 + 该轮每个说话人的回复）→ 每轮生成完成（`Complete`）时除最后一条外全被从本地列表删除。数据落库完整，退出重进即恢复。改为按 `transcriptKey`（`turnId\|speaker\|timestamp\|正文哈希`）逐条去重 | **2.2.1** |
| **会话 `transcript_count` 与实际条数脱钩** | 6 处写 `transcript`，只有 2 处同步写计数：纠错（删几条插几条）、分支（截断为前缀）、场景切换（追加 1 条）、临时 NPC 插件（追加 2 条）都直接替换数组就落盘，而共用的 `saveSession()` 从不重算 → 真机上「声明 179 / 实际 178」，影响「还有更多历史」判定、翻页 offset 与增量补齐判据。修复：写入侧在会话清单的**唯一写入口**统一对齐，分支额外归零 `transcript_start`，读取侧以「归档偏移 + 数组长度」为准并自愈存量数据 | **2.2.2** |
| 离开对话页报 `stop failed: not bound to TTS engine` | TTS 引擎在**进入对话页**时就创建（绑定系统服务），而 `onDispose` 只调 `stop()`、从不调 `shutdown()` → 每次进出泄漏一个实例与它的 ServiceConnection；绑定是异步的，没点过朗读时 `stop()` 就会打这条警告。改为首次朗读时才绑定、页面销毁时 `shutdown()` | **2.2.2** |

## 约定与边界

- **数据在你本机**：书卷、会话、模型配置都存在应用私有目录；诊断数据仅存本机，**导出由你手动触发**。
- **密钥**：经 **Keystore** 加密存储（`AndroidServerPlatform.secureStore`）。
  密钥**不会**出现在日志或诊断导出里——脱敏发生在写入侧。
- **native 崩溃**：目前能拿到「发生了 native 崩溃 + 信号 + 进程死因」，**拿不到完整 native 堆栈**（需要引入 Crashpad，尚未做）。
- **旧书卷**：没有逐章弧线的旧书卷会退回「单一人物档案」行为，无需迁移；想让旧书卷带上弧线，重新整理一次即可。
